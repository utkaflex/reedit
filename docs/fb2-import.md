# Импорт FB2 · дополнительный этап 04B

В библиотеке — «Импорт FB2», в карточке — «Прикрепить FB2». Выбор, проверка в памяти, превью метаданных/обложки, создание новой книги или прикрепление к существующей, отмена и подтверждение используют тот же сценарий, что EPUB. Исходный FB2 не загружается на сервер. До подтверждения нет записей в БД.

## Архитектура и неизменность оригинала

`DocumentAdapter` реализует существующий порт EpubAdapter и выбирает формат по расширению. Обычные EPUB делегируются прежнему EpubJsAdapter. Отдельный Fb2Adapter безопасно разбирает XML и создаёт локальный EPUB 3, который проходит полный существующий EPUB-анализатор: ZIP/CRC, ресурсы, manifest/spine, безопасность XHTML/CSS, метаданные и текстовый индекс. EPUB-импорт не заменён вторым парсером.

BookFile.data — точные исходные байты FB2, mediaType=`application/x-fictionbook+xml`, sha256 — хеш именно оригинала. Необязательный BookFile.representation содержит format=epub, converterVersion=1, sourceSha256, отдельный SHA-256 и Blob производного EPUB. EpubIndex описывает manifest/spine производного документа, но связан с UUID и SHA исходного файла. Ни преобразованным файлом, ни текстовым индексом оригинал не подменяется.

Новые поля необязательны для существующих EPUB. Таблицы/индексы IndexedDB не меняются: схема остаётся v5; миграция с чтением/перезаписью старых Blob не нужна. Валидация требует полноценное представление у FB2 и запрещает его у обычного EPUB. Весь BookFile после создания остаётся неизменяемым.

Оригинал, производный Blob, EpubIndex и новая Book/Reading (если нужны) фиксируются одной прежней транзакцией commitEpubImport. Quota/abort откатывают всё. SHA-дедупликация использует оригинальные байты: повторный FB2 возвращает прежний файл, не меняя метаданные, отзыв, оценку или прочтения. Прикрепление к существующему Book не создаёт Reading и не заменяет пользовательские поля. Удаление файла удаляет оба Blob и производные индексы, сохраняя книгу/историю/заметки/закладки.

При открытии DocumentAdapter сверяет SHA исходного FB2. Общая читалка проверяет SHA производного EPUB и его spine существующим адаптером, затем открывает сохранённые байты через тот же epub.js. ReadingCursor/DocumentTextIndex сохраняют идентичность исходного FB2; CFI и DOM mappings относятся к его неизменному производному EPUB. Представление не пересоздаётся при открытии и не обновляется автоматически при новой версии конвертера. Поэтому прежние CFI не зависят от изменений программы конверсии.

## Поддержанное содержание

Корень FictionBook и элементы используют namespace `http://www.gribuser.ru/xml/fictionbook/2.0`, включая варианты с namespace prefix. Метаданные берутся из title-info: book-title; составные имена author или nickname; annotation с абзацами; lang; coverpage/image со ссылкой на binary. Metadata document-info не выдаётся за авторов произведения.

Все body обрабатываются в исходном порядке. Заголовок, начальное изображение и эпиграфы body сохраняются перед секциями как отдельная часть; каждая верхняя section становится следующим XHTML. Вложенные section, абзацы, title/subtitle, epigraph/cite, poem/stanza/v, text-author/date, empty-line, таблицы, strong/emphasis/strikethrough/sub/sup/code/style и изображения проходят последовательный обход DOM. Пунктуация и inline-границы сохраняются. Строки стихов остаются отдельными абзацами, строфы — группами. Оригинальная декорация style не переносится.

Notes-body не теряется и не прячется только в оглавлении: это последующие линейные части в исходном порядке. Внутренние ссылки и обратные ссылки переписываются на нужный XHTML/ID; percent-encoded фрагменты поддерживаются. Исходные id отображаются на безопасные генерируемые id, повторные id запрещены. Вложенные секции без id получают стабильные id для оглавления. Оглавление не определяет полноту текста.

Встроенные PNG/JPEG/WebP из binary декодируются из Base64 локально, проверяются по сигнатуре и размерам до использования декодером. Лимит изображения — 8 МБ, 6000×6000, 20 млн пикселей; суммарный бинарный объём — 16 МБ, максимум 512 ресурсов. Обложка сохраняется как локальный raster Blob в Book. В XHTML используются только генерируемые локальные имена ресурсов, без путей из XML.

## Безопасность, ошибки и пределы

- Вход: обычный `.fb2` до 16 МБ. Поддерживаются UTF-8, UTF-16 с определяемым порядком байтов, Windows-1251/CP1251 и KOI8-R с XML declaration; противоречащий BOM отвергается.
- DOCTYPE и объявления любых ENTITY отвергаются до DOMParser. Внешние сущности не разрешаются; XSD/DTD не загружаются. Processing instructions и чужие namespaces запрещены. Разбор XML инертный; source DOM никогда не вставляется в интерфейс.
- Конверсия создаёт только разрешённые XHTML-элементы через DOM API; текст и metadata экранируются. Обработчики событий, script и неизвестный контент завершают импорт ошибкой; текст не пропускается ради успешного импорта.
- Stylesheet FB2 остаётся в оригинале, но не применяется; отображается предупреждение. Стили читалки/конверсии статические. HTTP(S)/mailto-ссылки остаются обычным текстом с предупреждением, небезопасные схемы запрещены. Изображения должны ссылаться на встроенный binary; удалённые ресурсы не загружаются.
- Повреждённый XML/Base64, повторный id, отсутствующая картинка/внутренняя ссылка, пустой body, неизвестный элемент или превышение пределов дают явную ошибку без частичных записей.
- Сохраняются пределы EPUB-проверки: до 4 МБ на один XHTML, 64 уровня/100000 XML-элементов, общий объём и число ресурсов ограничены. Конвертер допускает до 1024 частей. XML разбирается нативно в пределах размера; обход/конверсия и декодирование бинарных буферов кооперативные, AbortSignal проверяется между порциями. Уже выполняющийся XML-разбор/DEFLATE нельзя прервать посередине, но после отмены записи не создаются.

Это проверенный поднабор FB2, не полноценная XSD-валидация. FB2.ZIP/FBZ, GIF/SVG и другие MIME binary, внешние изображения, неизвестные расширения содержимого и слишком большие части пока не поддержаны. Они не удаляются молча — импорт заканчивается понятной ошибкой. Полное издательское оформление FB2 не воспроизводится; текст, порядок, базовая семантика, локальные изображения и ссылки сохраняются.

## Проверки

Синтетические оригинальные тексты/изображение в tests/fixtures/fb2.ts — CC0-1.0, не пользовательские данные. Ожидаемые части заданы независимо от конвертера. Проверяются их число, порядок и нормализованный полный текст; отдельно создаётся эквивалентный EPUB и сравниваются текст/количество слов. Проверяется повторный анализ производного EPUB, метаданные, обложка, кодировки, ссылки, стихи, детерминированность, XXE/DTD/PI/XSS, неизвестные элементы, Base64/ресурсы, отмена, quota, дубли, reopen, прикрепление без изменения личных данных и удаление файла без удаления истории.

E2E Chromium desktop/mobile: системный file input → FB2 → превью → IndexedDB → общая читалка → изображение с naturalWidth>0 → примечание → reload → восстановление места. Сверяются точный исходный FB2, разные хеши оригинала/представления, source SHA в курсоре и одинаковый DocumentTextIndex независимо импортированных FB2/EPUB. Контролируются отсутствие внешних запросов и отсутствие лишних записей после дубля/опасного XML.

Вручную на физическом iPhone: выбор .fb2 в Files/iCloud Drive, большой файл, UTF-16/Windows-1251, стихотворения/изображения/таблицы, примечания и обратные ссылки, отмена, нехватка места, закрытие/перезапуск и VoiceOver. WebKit Windows ранее воспроизводил отказ нативной записи Blob без кода приложения; Chromium emulation не подтверждает Safari-совместимость.

Первичный источник формата: [FictionBook XSD проекта Дмитрия Грибова](https://github.com/gribuser/fb2/blob/master/FictionBook.xsd). Схема использовалась как справочник структуры; её код в проект не копируется и XSD не загружается приложением.
