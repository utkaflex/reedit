# Локальный импорт EPUB · этап 04

После проверки на iPhone разрешено пассивное объявление Content-Type с UTF-8/UTF-16. Отсутствующий якорь внутри существующего документа теперь даёт предупреждение, но не блокирует чтение полного текста. Отсутствующий файл ресурса по-прежнему блокирует импорт. Подробности и регрессии — [iphone-hotfix.md](iphone-hotfix.md).

Дополнительный формат FB2 подключён отдельным адаптером, не заменяя этот EPUB-парсер. Оригинал FB2 и его производный EPUB сохраняются вместе; детали — fb2-import.md.

## Сценарий

В библиотеке — «Импорт EPUB», в карточке — «Прикрепить EPUB». Системный file picker принимает `.epub`. После выбора выполняется проверка в памяти. Пользователь видит название, авторов, язык, встроенную растровую обложку, SHA-256, количество линейных ресурсов и слов; затем явно выбирает новую либо существующую книгу и подтверждает сохранение. До этого в БД нет ни временной книги, ни файла, ни индекса.

Новый Book получает извлечённые метаданные и отдельный planned Reading. При прикреплении к существующему Book метаданные, обложка, оценки, отзывы, Reading и ранее прикреплённые файлы остаются без изменений. Позиции старых EPUB автоматически не переносятся. Повторный SHA-256 открывает существующую запись, не создавая копии и не меняя историю. При совпадении только метаданных действует предупреждение о дубле книги; отдельная запись требует явного согласия.

Оригинал хранится как Blob с исходными байтами. Его нельзя изменять через репозиторий; другая редакция EPUB получает новый UUID. Файл не разбивается, не перепаковывается, не загружается на сервер и не регистрируется в Cache Storage. Анализ использует только выбранные байты, без URL-запросов за содержимым книги.

## Граница адаптера

`domain/epub.ts` — порт EpubAdapter, DTO анализа и типизированные ошибки. `infrastructure/epub/EpubJsAdapter.ts` — реализация. В composition root она загружается динамически только при первом импорте. UI не знает об epub.js или JSZip. `services/epub-import.ts` координирует анализ, проверку SHA и формирование транзакционного запроса.

epub.js 0.3.93 разбирает OPF (Packaging) и EPUB 3 navigation / EPUB 2 NCX (Navigation). Renderer, Book.open, iframe, renderTo и автозагрузка ресурсов не используются. Это позволяет проверить неподдерживаемые и небезопасные книги до любых действий отображения. Собственного дублирующего OPF/NCX-парсера нет: проверки XML-структуры/ссылок и атрибутов дополняют библиотечный парсер политикой импорта.

JSZip 3.10.2 — тот же совместимый ZIP-декодер, который использует epub.js. Прямое объявление зависимости необходимо для доступа к контейнеру до разбора OPF. Узкая проверка центральных/локальных ZIP-заголовков выполняется до распаковки: публичный JSZip API не предоставляет безопасную предварительную проверку размеров, перекрытий и повторяющихся исходных путей. DEFLATE реализует только JSZip. Его публичный internalStream позволяет остановить чтение при превышении лимита; небольшая декларация дополняет отсутствующий метод в поставляемых типах. CRC считается на ограниченных выходных чанках: checkCRC32=true у JSZip сам распаковывает ресурсы до пользовательских лимитов, поэтому здесь не используется.

Устаревшая транзитивная XML-зависимость epub.js заменена совместимой веткой `@xmldom/xmldom ^0.8.15` через pnpm override. В браузере разбор выполняет нативный DOMParser. Необязательные postinstall core-js/es5-ext запрещены, build script esbuild остаётся разрешённым. jsdom 26 — только DOM-среда тестов с совместимостью текущего Node toolchain; в production не включён.

## Проверки контейнера и ресурсов

1. Расширение и размер файла; чтение с отдельной ошибкой и сверкой количества байт. MIME от ОС не является источником истины: действительный тип проверяется по ZIP и его обязательному mimetype. SHA-256 через Web Crypto в HTTPS/localhost.
2. Сигнатуры и границы ZIP, единственный диск, отсутствие ZIP64, STORE/DEFLATE, отсутствие ZIP-шифрования. Записи не перекрываются; имена, локальные заголовки, размеры и CRC согласованы. `mimetype` — первый несжатый ресурс с точным содержимым `application/epub+zip`.
3. Отклоняются абсолютные пути, traversal, backslash, управляющие символы, символические ссылки, повторные/неоднозначные пути. У каждого ресурса проверяются реальный распакованный размер и CRC. Ограничение применяется во время чтения, а не только к заявленным размерам.
4. Нужны META-INF/container.xml и один корректный OPF rootfile с metadata, manifest, spine. EPUB 2/3; уникальные manifest id/пути, существующие idref и допустимые значения linear. Все заявленные manifest-ресурсы должны находиться в ZIP.
5. Проверяется каждый XML/XHTML/SVG, в том числе нелинейный и неиспользуемый. Проверяются локальные src/href, NCX content, CSS url(), srcset, изображения, шрифты и фрагменты. Сетевые ресурсы не загружаются и отклоняются; обычные внешние гиперссылки a/area остаются лишь неисполняемыми данными. XML с ошибками или неподдерживаемой кодировкой не исправляется с потерей текста.

## Spine — источник порядка и полного объёма

Индекс строится по массиву spine из OPF в исходном порядке, не по ZIP, именам файлов, navigation или NCX. Сверяются количество и idref библиотечного парсера с исходным spine. Значение linear по умолчанию yes. У каждого линейного itemref должна быть запись sections с тем же path и spineIndex — даже если она содержит ноль слов. Нелинейные ресурсы сохраняются в manifest/spine и оригинале, но не включаются в последовательный текстовый индекс. Неизвестный линейный media-type даёт явную ошибку, а не пропуск; поддержаны XHTML и SVG.

Для XHTML берутся текстовые узлы body, для SVG — текст документа. Комментарии, head и style не являются текстом книги. Между блоками вставляется разделитель, внутри inline-слов — нет: `Сло<em>во</em>` остаётся «Слово». Нормализация — Unicode NFC, последовательности whitespace превращаются в один пробел, крайние пробелы убираются. Скрытый текст и примечания body не отбрасываются. Оригинальные XHTML и CSS не переписываются. OCR изображений не выполняется.

EpubIndex хранит версию индекса/политики, SHA-256, метаданные, OPF path, manifest, весь spine, вложенную navigation и sections `{path, spineIndex, text, wordCount}`. totalWords/totalCharacters сверяются с sections. Это основа будущего поиска и статистики; текущий библиотечный поиск и экран статистики не расширяются заранее.

## Безопасность и DRM

META-INF/encryption.xml, rights.xml, license.lcpl и ZIP encryption отклоняются с объяснением. Обфускация шрифтов тоже пока не поддержана и не выдаётся за обычный незашифрованный файл. Защита не снимается, DRM не обходится.

Отклоняются script/scripted/JS-ресурсы, обработчики on*, javascript/vbscript, srcdoc, iframe/frame/object/embed, формы/активные элементы, SVG foreignObject/SMIL, base/xml:base, активные meta-директивы, XML ENTITY/internal DTD, активный CSS и CSS @import. Код не вырезается с последующим «успешным» импортом: пользователь получает отказ. XML разбирается в неактивных документах и никогда не вставляется в DOM приложения. Метаданные выводятся React как текст, не HTML.

Превью обложки использует только PNG/JPEG/WebP. Перед передачей в image decoder проверяются сигнатура и размеры заголовка. SVG-обложка остаётся в оригинале и даёт предупреждение вместо небезопасного превью. Это политика текущего импорта, а не универсальная гарантия безопасности файла: будущая читалка обязана использовать собственную изоляцию, запрет скриптов/внешних ресурсов и защиту вывода. Не передавать оригинал прямо в неограниченный renderTo.

## Лимиты и неподдерживаемые варианты

| Ограничение              | Значение                       |
| ------------------------ | ------------------------------ |
| Выбранный EPUB           | 32 МиБ                         |
| Всего распакованных байт | 64 МиБ                         |
| Один ZIP-ресурс          | 8 МиБ                          |
| Количество ZIP-записей   | 2048                           |
| Один XML/XHTML           | 4 МиБ                          |
| XML-узлы / глубина       | 100000 / 64                    |
| Нормализованный текст    | 16×1024×1024 символов          |
| Растровая обложка        | до 6000×6000 и 20 млн пикселей |

Превышение лимита — отказ без обрезания. Многотомные/ZIP64, несколько rootfile, произвольные кодировки, custom entities, зашифрованные/обфусцированные ресурсы, CSS @import, remote media, foreign-content spine/fallback и большие архивы пока не поддержаны. Это проверенный поднабор EPUB, не замена официального EPUBCheck. Разбор одного ограниченного XML или SHA-256 нельзя мгновенно прервать внутри нативной операции; проверка отмены выполняется между шагами/ресурсами. Между ресурсами управление возвращается event loop.

## Атомарность и миграция v3

V1 и v2 сохраняются. V3 добавляет Book.language=null и BookFile.sha256=null старым записям, индекс `&sha256` (null не индексируется) и новую таблицу epubIndexes с уникальным bookFileId. Старые Blob, UUID, даты, отзывы, коллекции и прочтения не меняются и не анализируются в миграции. У старых файлов нет автоматически построенного индекса; дедупликация по SHA гарантирована для файлов, импортированных начиная с этапа 04.

`commitEpubImport` повторно проверяет SHA внутри одной readwrite-транзакции. Новый Book + начальный Reading + BookFile + EpubIndex сохраняются вместе. При прикреплении создаются только BookFile/индекс. Удаление/изменение целевого Book другой вкладкой не создаёт висячую связь. Любая ошибка, включая quota или abort, откатывает все записи; исходные данные сохраняются. Код ошибки quota не теряется при прохождении вложенных репозиториев.

AbortSignal действует на чтение, распаковку, анализ и активную транзакцию. До подтверждения никаких записей нет. После фактического commit операция завершена; поздняя отмена не удаляет успешно импортированную книгу. Удаление BookFile удаляет его производный индекс, но сохраняет Book/Reading/Annotation/Bookmark; удаление Book по подтверждению удаляет также индексы принадлежащих ему файлов.

## Фикстуры и проверки

`tests/fixtures/epub.ts` создаёт оригинальные синтетические EPUB; `pnpm fixtures:epub` воспроизводит файлы в `tests/fixtures/epubs`. Лицензия CC0-1.0, никаких защищённых книжных текстов. expected.json содержит исходные ожидаемые нормализованные тексты и линейные пути независимо от анализатора. Фикстуры не добавляются в пользовательскую библиотеку при запуске.

- one-chapter: одна глава в одном XHTML; repeat-identical — те же байты под другим именем.
- split-chapter: одна глава в нескольких XHTML, порядок ZIP отличается от spine.
- parts-sparse-toc: четыре части с одной ссылкой в оглавлении.
- epub2 и EPUB 3, длинный русский текст, inline-слова, иллюстрация/обложка.
- broken-links, missing-spine-resource, damaged, DRM, активный script; дополнительные опасные случаи генерируются тестами.

Unit/integration-тесты сравнивают количество/порядок текстовых ресурсов и нормализованный текст до/после анализа и после IndexedDB, байты оригинала, SHA, конкурентный повторный импорт, сохранность пользовательских данных, отказ записи индекса и отмену транзакции. Браузерные сценарии дополнительно проверяют reload, системный file input, отказ для DRM/скриптов и отсутствие POST/внешних запросов за книгой.

Ручная проверка: физический iPhone Safari, выбор из Files/iCloud Drive, EPUB разных издательств в указанных лимитах, отмена во время обработки, отказ места, повторный файл с другим именем, прикрепление к книге с историей. WebKit Playwright в текущей Windows-среде блокируется политикой DLL; Chromium emulation его не заменяет. Читалка этапа 05 описана отдельно в reader.md; гарантии импорта сохраняются.

Первичные источники: [EPUB 3.3 / spine и OCF](https://www.w3.org/TR/epub-33/), [epub.js](https://github.com/futurepress/epub.js), [JSZip internalStream](https://stuk.github.io/jszip/documentation/api_zipobject/internal_stream.html), [Dexie migrations](<https://dexie.org/docs/Version/Version.upgrade()>).
