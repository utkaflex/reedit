# Развёртывание Reedit на Railway

Подготовлен один Docker-сервис: статическая PWA и существующий ограниченный proxy каталогов. База данных, Volume и отдельные сервисы не нужны. Пользовательские книги и резервные копии не входят в образ. Развёртывание выполняет владелец репозитория; действующего адреса у этой подготовки нет.

## Действия владельца

1. Сохраните изменения проекта в Git и отправьте их в свой репозиторий. Файлы должны появиться в GitHub до подключения Railway. Не добавляйте `.env`, личные EPUB/FB2, резервные копии и профили браузера. `.gitignore` исключает книги/ZIP, оставляя только синтетические тестовые EPUB; `.dockerignore` дополнительно ограничивает состав сборки.
2. В Railway создайте проект через Deploy from GitHub repo, выберите репозиторий Reedit и корень проекта. Railway использует `railway.json` и `Dockerfile`. Отдельные Build/Start Command не задавайте: они уже определены образом.
3. Дождитесь сборки и успешной проверки `/healthz`. Сервер слушает `0.0.0.0` и переменную `PORT`; не фиксируйте порт локальной разработки вручную.
4. В настройках Networking создайте публичный домен. Открывайте приложение по HTTPS. При собственном домене настройте его по инструкции Railway. Если автоматический `RAILWAY_PUBLIC_DOMAIN` не подходит для вашего домена, задайте `APP_ORIGIN=https://ваш-домен` без пути.
5. При необходимости добавьте серверные переменные `GOOGLE_BOOKS_API_KEY` и `CATALOG_CONTACT` (реальный контакт сопровождающего). Ключ не должен иметь префикс `VITE_` и не включается в клиентскую сборку. Без Google-ключа личная библиотека продолжает работать; Google-поиск недоступен. Каталоги требуют интернета.
6. После запуска выполните проверки ниже. Никаких архивов книг на Railway загружать не требуется.

Домен определяет хранилище браузера. Данные с localhost, другого домена или другого браузера автоматически не перенесутся. До смены адреса экспортируйте ZIP с файлами и сохраните вне приложения. На постоянном HTTPS-адресе восстановите копию через Настройки с предварительной проверкой и подтверждением. Не очищайте данные сайта для исправления обновления.

## Проверка опубликованного адреса

- `/healthz` отвечает 200 и `{"status":"ok"}`; `/manifest.webmanifest` имеет MIME `application/manifest+json`.
- `/sw.js` имеет `Cache-Control: no-cache`, MIME JavaScript и область `/`. Хешированные JS/CSS имеют `immutable`; HTML перепроверяется. Поддерживающий клиент получает Brotli/gzip.
- Прямой переход `/library` открывает оболочку; неизвестный `.js`, `.env`, EPUB/FB2 и ZIP не выдаются сервером. Навигация приложения использует hash-ссылки.
- Импортируйте собственную книгу, измените оформление, сохраните цитату и позицию, закройте и откройте приложение. Проверьте RSVP/Guided и возврат к слову.
- Сохраните полную ZIP-копию, восстановите её и проверьте отзывы, цитаты, файлы и позицию. Оригинальную копию оставьте вне приложения.
- Дождитесь готовности офлайн-оболочки, включите авиарежим, полностью закройте приложение и откройте снова. Первый запуск без предварительного посещения онлайн невозможен.
- На следующем развёртывании открытая книга не должна принудительно перезагружаться; примените обновление после выхода из чтения и проверьте данные.

На физическом iPhone отдельно проверьте установку Safari → Поделиться → На экран «Домой», safe-area в обеих ориентациях, длинное нажатие и границы выделения, системное меню, клавиатуру заметки, блокировку экрана, выгрузку приложения и повторный офлайн-запуск. Эти проверки не заменяются эмуляцией viewport.

## Локальная production-проверка

Node 24, pnpm 11.25.0: `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm start`. Открыть `http://localhost:4174`. Переменные окружения задаются процессу; `.env.example` — справочник, сервер не загружает `.env` автоматически. `pnpm preview` предназначен для просмотра Vite-сборки, а не проверки production-заголовков.

При установленном Docker: `docker build -t reedit .`, затем `docker run --rm -p 8080:8080 reedit`. Локальная среда этого аудита не содержит Docker, поэтому сборка образа должна быть подтверждена Railway. Сервер и клиентская сборка проверяются отдельно автоматическими тестами.

Откат кода не должен запускать приложение со схемой старее уже установленной IndexedDB. Перед откатом проверьте совместимость миграций и сохраните ZIP. Service Worker не удаляет IndexedDB. Не добавляйте очистку базы в deploy/start.

Официальные источники: [config as code](https://docs.railway.com/config-as-code), [healthchecks](https://docs.railway.com/deployments/healthchecks). Расходы определяются вашим тарифом и использованием одного сервиса.
