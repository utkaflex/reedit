# Модель данных · v7

Все записи имеют `id` (локальный UUID), `createdAt`, `updatedAt` (целые миллисекунды Unix UTC). createdAt неизменяем, updatedAt не убывает и не меньше createdAt. Генерация через crypto.randomUUID требует secure context (HTTPS или localhost). ISBN и catalogIds не являются ключами и не обязаны быть уникальными.

V3: Book дополнен `language: string | null`; BookFile — `sha256: string | null` с уникальным индексом для не-null значений. Новые импортированные файлы всегда имеют SHA-256; старые файлы сохраняются с null без чтения/перезаписи содержимого при миграции. BookFile после создания неизменяем: другой оригинал — другой UUID.

Новая сущность EpubIndex: UUID и timestamps, уникальный `bookFileId → BookFile`, SHA-256, версии индекса/политики, OPF path, версия EPUB, метаданные, manifest, весь spine/navigation, sections с текстом каждого линейного ресурса, totals. Index не принадлежит конкретному Reading: повторные прочтения могут пользоваться тем же файлом и индексом. Удаление файла удаляет только его производный индекс и отвязывает позиции/заметки/закладки; книга и история остаются. Подтверждённое удаление Book удаляет также индексы её файлов.

`commitEpubImport` атомарно создаёт файл/индекс, а при выборе новой книги также Book/Reading. Уникальность SHA повторно проверяется в транзакции: идентичный импорт возвращает существующие идентификаторы без изменений пользовательских записей. Модель проверяет соответствие sections каждому линейному spine itemref и итоговые размеры. Подробности и лимиты в epub-import.md.

| Сущность        | Назначение и связи                                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Book            | Запись библиотеки: непустое название, авторы, описание, жанры, ISBN[], catalogIds[], cover: Blob или null                   |
| BookFile        | Оригинальный Blob EPUB/FB2; для FB2 неизменное EPUB-представление; bookId → Book; файлов может быть несколько               |
| Reading         | Конкретное прочтение, bookId → Book; planned / active / finished / paused / abandoned, даты, rating: 0,5…5 или null, review |
| ReadingPosition | Текущая позиция Reading+BookFile: CFI, текстовый progression, необязательный ReadingCursor, nullable bookFileId             |
| Annotation      | bookId, readingId → Reading, CFI Range, TextAnchor, цитата, комментарий, цвет, nullable bookFileId                          |
| Bookmark        | bookId, readingId → Reading, CFI, TextAnchor видимого фрагмента, подпись, nullable bookFileId                               |
| ReadingSession  | readingId → Reading, начало/конец, активные секунды не больше длительности                                                  |
| Collection      | Непустое имя, уникальный массив bookIds → Book                                                                              |
| Settings        | UUID, уникальный key=local, theme=system/light/dark, locale=ru, необязательные reader-настройки                             |

У planned обе даты null; у active начало задано, конец null; у finished обе даты заданы, конец не раньше начала. Нулевой прогресс допустим. Повторное чтение создаёт новый Reading UUID, история остаётся у прежнего прочтения.

У paused начало необязательно, конец null. У abandoned обе даты необязательны, но конец допустим только при известном начале и не раньше него. Оценка принимает половинные значения от 0,5 до 5; null означает отсутствие оценки. Оценка и личный отзыв принадлежат конкретному Reading, а не книге в целом.

Статус и оценка в библиотеке выводятся по последнему созданному Reading; ручное изменение дат не меняет порядок прочтений. У старой книги без Reading отображается «Хочу прочитать» без оценки. «Добавить прочтение» создаёт planned с отдельным UUID и пустыми датами/оценкой/отзывом, сохраняя всю историю. Даты, введённые календарём, записываются в UTC-полночь выбранного дня; их отображение не сдвигается при смене часового пояса. Исторические временные метки v1 не переписываются.

Обложка — локальный Blob JPG/PNG/WebP до 10 МБ, выбранное изображение проверяется браузером (до 6000×6000). Удаление обложки не затрагивает BookFile. Для отображения создаётся временный Blob URL, который освобождается при смене/размонтировании. В БД сохраняется сам Blob, а не URL и не путь к пользовательскому файлу.

## Миграция v4 → v5 · единая позиция

Дополнение 04B без DDL-миграции: BookFile.mediaType допускает application/x-fictionbook+xml. data и sha256 всегда относятся к оригиналу. У FB2 обязательно representation: format=epub, converterVersion=1, sourceSha256, собственный sha256 и data: Blob EPUB. У обычного EPUB representation отсутствует. Валидация и неизменяемость BookFile распространяются на всю пару оригинал/представление. Существующие записи v5 остаются без изменений.

EpubIndex FB2 описывает производный EPUB и связан с оригиналом через bookFileId/source SHA. DocumentTextIndex и ReadingPosition.cursor тоже используют source SHA; проверка отображаемых EPUB-байтов выполняется по отдельному representation.sha256. Идентификаторы книг, прочтений и их история не зависят от source XML id. Подробности и правила удаления — fb2-import.md.

Добавлена таблица DocumentTextIndex: UUID, timestamps, bookFileId, SHA-256, algorithmVersion, segmentation, sections с текстом/токенами/исходными DOM mappings и totalCharacters. Ключ `[bookFileId+sha256+algorithmVersion]` уникален. Это производные данные конкретного файла, независимые от Reading; подробные правила — positions.md. Старый EpubIndex импорта остаётся неизменным и проверяет полноту исходного spine.

ReadingPosition.cursor необязателен для прежних записей. Новые позиции содержат hash/версию/spineIndex/UTF-16 offset/тип якоря. Репозиторий атомарно проверяет родительский файл, наличие соответствующего индекса, границы курсора и совпадение progression с текстовым объёмом. Чтения и файлы имеют независимые позиции, индекс разделяется между прочтениями. При удалении файла производный кеш удаляется, а CFI/cursor остаются с null bookFileId. Повторный файл не получает старую позицию автоматически.

Миграция только добавляет таблицу: прежние UUID/CFI/progression/Blob/настройки не меняются. Индекс строится лениво, а legacy CFI преобразуется при успешном открытии после relocated. Кеш сохраняется целиком; quota/отмена не создают частичных sections. Конкурентная запись возвращает существующий индекс. Изменение нормализации/DOM-канонизации требует новой algorithmVersion.

### Историческая миграция v3 → v4

V4 сохраняет все версии v1–v3 и меняет только индексы positions: снимает уникальность readingId, добавляет уникальную пару readingId+bookFileId. Ни UUID, ни CFI, ни timestamps, ни Blob не переписываются. Null bookFileId не входит в составной индекс: позиции отвязанных файлов сохраняются независимо и не объединяются. Новая читалка записывает только позиции с существующим файлом через транзакционный saveReaderPosition.

Settings.reader необязателен для старых записей; при отсутствии применяются чистые defaults без записи в БД. В нём хранятся mode, font, fontSize, lineHeight, margin, alignment, theme, animations (ограничения — reader.md). Сохранение сохраняет UUID, locale и тему приложения, проверяет expectedUpdatedAt. Начальное чтение не создаёт Settings. Открытие с прежним CFI разрешено только для той же пары Reading+BookFile.

## Миграция v1 → v2

Схема v1 не изменяется задним числом. V2 добавляет индексы createdAt для books/readings и значения по умолчанию только отсутствующим новым полям: Book.description='', genres=[], cover=null; Reading.rating=null, review=''. Ни одна старая запись не удаляется и не заменяется. Settings, коллекции, EPUB Blob, позиции, заметки, закладки и сессии не преобразуются. Все изменения выполняются в upgrade-транзакции. При отказе записи миграция откатывается; после устранения причины её можно повторить. Тесты создают настоящую базу v1 и проверяют успешное обновление и откат при ошибке.

Файл позиции/закладки/аннотации должен принадлежать той же книге, что Reading. Перенос существующей записи на другого родителя запрещён. Индекс &[readingId+bookFileId] гарантирует единственность текущей позиции для конкретного прочтения и файла, &key — Settings. Остальные внешние ключи проверяются в транзакциях репозиториев: IndexedDB не поддерживает foreign keys.

## Удаление и повторное прикрепление

`removeBookFile(id)` удаляет только Blob-запись и устанавливает bookFileId=null у позиций, аннотаций и закладок. Сами записи, CFI, цитаты, прочтения и книга сохраняются. К новому EPUB создаётся новый BookFile UUID. Точная привязка TextAnchor восстанавливается при повторном импорте того же original+rendered SHA в ту же Book; старые CFI без TextAnchor автоматически не привязываются: одинаковое название или ISBN не доказывает совместимость редакций.

`removeBook(id, {confirmed:true})` — отдельная явно подтверждаемая операция: удаляет книгу с обложкой, все её файлы и прочтения вместе с позициями, аннотациями, закладками и сессиями; исключает bookId из коллекций, сохраняя сами коллекции. Вся операция атомарна. UI показывает последствия и требует отдельного подтверждения. Универсального delete у репозиториев нет. `removeCollection` требует подтверждения и удаляет только коллекцию; книги сохраняются.

При ручном добавлении ISBN проверяется по контрольной сумме. Предупреждение о дубле возникает при совпадении ISBN (включая эквивалентные ISBN-10/13) либо нормализованного названия и набора авторов. Можно открыть существующую книгу или явно сохранить отдельный экземпляр. Автоматического слияния нет. Проверка и запись выполняются атомарно, включая параллельное добавление.

Изменять данные следует только через LocalStore. Низкоуровневый Dexie является внутренней инфраструктурой. Валидация MIME/Blob пока не является проверкой EPUB-архива; анализ содержимого относится к будущему импорту.

## V6: аннотации

Добавлены индексы bookId/createdAt в annotations/bookmarks. Миграция дополняет bookId из Reading и отсутствующий color=yellow, сохраняя оригиналы и все старые поля. В TypeScript bookId/anchor/color допускают отсутствие исключительно для legacy-записей; новые цитаты требуют bookId и проверенный TextAnchor. TextAnchor: contentId originalSHA:renderedSHA, start/end ReadingCursor, before/after до 48 символов. Quote и привязка неизменяемы; note/color/label обновляются с expectedUpdatedAt. removeSaved — отдельное подтверждённое в UI удаление с проверкой updatedAt. Подробные инварианты, идемпотентность и разрешение повреждённых CFI — [annotations.md](annotations.md).

## Скорочтение (08)

Settings.speed опционален: WPM 100–900, focusLetter, guidedWords 1–12, longWordLength 4–40, пять множителей пауз 0.5–6. Отсутствие поля означает стартовые настройки; версии схемы v6 и текстового индекса v1 остаются прежними. Режимы используют ту же ReadingPosition с ReadingCursor/CFI/progression и тот же Reading. SpeedDocument с границами абзацев и SpeedWord — производные данные в памяти, не новая пользовательская таблица и не новая редакция книги.

## V7: каталожные источники

Добавлена catalogSelections: локальный UUID/timestamps, bookId, source, editionId; отдельные ссылки record и edition с родительским workId; selectedCover; snapshot исходных Open Library metadata отдельно от пользовательских полей. Google snapshot не сохраняется. Уникален [bookId+source+editionId]. Book.publisher/publishedDate опциональны, старые Book не переписываются. saveCatalogBook атомарно создаёт Book/Reading/связь либо сопоставляет с существующим UUID с expectedUpdatedAt. Существующие Reading/файлы/позиции/аннотации не меняются; совпадение только названия не объединяет книги. removeBookFile сохраняет provenance, removeBook удаляет соответствующие catalogSelections. Подробности — catalog-search.md.

# Дополнение V8: статистика и дневник

`ReadingSession` получает необязательные поля mode, ownerId, state, leaseKey/leaseUntil, contentId, textVersion, wordCount. Они обязательны для новых отслеживаемых сессий; старые записи сохраняются без домысливания. `ReadingActivity` хранит Reading/session UUID, идентичность содержимого, режим, UTC from/to, активные milliseconds и полуоткрытые словесные интервалы. Запись события и накопленного времени сессии — одна транзакция. `JournalEntry` связан с Book и Reading, хранит civil day, body и UTC timestamps. `Settings.readingGoals` — год → целое 0…1000.

Обе новые таблицы переживают удаление BookFile; удаляются только при подтверждённом удалении Book (дневник также имеет отдельное подтверждённое удаление записи). Интервалы нельзя переносить между изданиями. Подробнее: [statistics.md](statistics.md).

# V9: резервные копии и локальное обслуживание

Аддитивная таблица maintenance с ключом local хранит epoch, lastBackupAt и includedFiles. Это локальные управляющие данные, не пользовательские сущности и не переносимая часть копии. Записи V1–V8 и Blob не преобразуются. Старая вкладка после изменения epoch может читать, но не изменять восстановленную библиотеку без перезагрузки. Полная замена всех переносимых таблиц и epoch — одна readwrite-транзакция с rollback. Сессии в копии приостановлены, без lease/owner; metadata-only сохраняет цитаты/cursor/статистику с null fileId. Подробности — [backup.md](backup.md).
